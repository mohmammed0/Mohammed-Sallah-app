# OSS inventory

The machine-readable direct inventory is `oss-inventory.json`; the complete transitive graph is generated as CycloneDX JSON at `artifacts/sbom.cdx.json` by `pnpm run sbom:generate`. `pnpm licenses:check` evaluates every installed package.

The M2 scanner also has a container-specific CycloneDX 1.6 inventory at `artifacts/container-sbom.cdx.json`, generated by `pnpm sbom:container`. Its immutable inputs are ClamAV 1.4.6 at digest `sha256:e6444f72de025a3d57e2820dd1ad9f8734d1d4d6ab0e3336cdeb09fa2ba2f122` (GPL-2.0-only scanner project) and Node.js 24.19.0 Bookworm slim at digest `sha256:65932751ed4073ed02f5c04e494e4b2572a891b7dbea0568a863dc80341bf848` (MIT Node.js project, with Debian package licenses retained in image metadata). Both are Linux amd64 OCI image-manifest digests, not multi-platform index digests or local Docker image IDs. The inventory labels each config digest as the OCI manifest's config-descriptor digest. For ClamAV, generation proves the source through the repository digest and independently reads that config identity from Docker's saved image; the generated SBOM also records the platform and backend-dependent local image ID without treating those identities as interchangeable. The worker installs the MIT `@napi-rs/image-linux-x64-gnu` 1.13.0 binary for its actual Linux amd64 target. Other exact 1.13.0 platform binaries remain optional lockfile entries and are not all shipped in that image. The same worker installs FFmpeg 5.1.9-0+deb12u1 from the immutable Debian 2026-08-23 snapshot and exposes only fixed internal `ffmpeg`/`ffprobe` paths for bounded remux.

ClamAV hosted activation and image distribution are **NOT RUN**. The pinned image is repository/local operational evidence only; separate legal and operator approval must confirm applicable GPL source-offer and notice compliance before any distribution or hosted activation. It is not represented as permissive or production-approved.

The exact Debian FFmpeg 5.1.9 build is GPL-2.0-or-later and its dependent codec packages retain their individual licenses. Hosted activation and worker-image distribution are **NOT RUN** and require separate legal/operator approval plus applicable GPL source/notice compliance. Static JPEG/PNG/WebP still use full native decode/re-encode; approved M4A/MP4 audio and completion MP4 video use actual metadata-stripping stream-copy remux and reopen; PDF, WebM, unsupported codecs, and malformed containers fail closed.

## تحديث التبعيات | Dependency updates

تُراجع تحديثات Expo وReact والحزم المرتبطة بإصدار SDK معًا للحفاظ على توافق الجوال. يستثني Dependabot تحديثاتها الدورية الصغيرة من المجموعة العامة؛ تبقى تنبيهات الثغرات وتحديثات الأمان خارج هذا الاستثناء. يجب معالجة أي ثغرة بإصدار متوافق ومراجَع، مع إبقاء فحص Expo فعالًا.

The [Dependabot configuration](../../.github/dependabot.yml) reserves minor and patch version updates for Expo packages, the React runtime/renderers/types, and the installed SDK-managed native modules for a coordinated review. The root workspace rule also covers shared React packages used by web. Other package updates remain scheduled; major updates remain separate review proposals.

Use the [Expo upgrade procedure](https://docs.expo.dev/workflow/upgrading-expo-sdk-walkthrough/) to select the SDK and align its dependencies with `pnpm --filter @sallah/mobile exec expo install --fix` in a dedicated change. Run the existing `expo install --check`, `pnpm mobile:expo-doctor`, relevant tests, and `pnpm validate`; update the lockfile, `oss-inventory.json`, and `THIRD_PARTY_NOTICES.md` with reviewed license evidence. Compare newly added mobile dependencies with the installed Expo `bundledNativeModules.json` and extend the scheduled-update rules when needed.

Only explicit [SemVer update-type ignore rules](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference#ignore) are used. GitHub confirms that [these rules preserve security update PRs](https://github.blog/changelog/2021-05-21-dependabot-version-updates-can-now-ignore-major-minor-patch-releases/). Do not replace them with whole-package or version-range ignores, dismiss vulnerability alerts, or disable compatibility checks to accept an update. A security fix still needs a compatible SDK/runtime set and normal validation.

The final repository cleanup adopts the Next 16.3.4 security patch and reviewed SHA-pinned CI Actions. See [dependency review decisions](DEPENDENCY_REVIEW_2026-09-05.md) for adopted changes, deliberately retained versions and their future acceptance checks. Version and security-update automation remains enabled.
