# دليل تشغيل النسخة التجريبية المغلقة | Closed Beta Runbook

**البيئة:** `Preview` غير الإنتاجية فقط
**آخر تحديث مرجعي:** 2026-08-26
**الغرض:** تشغيل نسخة صلّح المغلقة ومراقبتها واستعادتها بأقل صلاحيات، من دون تحويل أي دليل محلي أو
اختبار اصطناعي إلى ادعاء إنتاج.

This runbook covers the nonproduction Preview environment only. It does not authorize Production,
public-store submission, billing changes, or the use of real personal data in operational checks.

## 1. حالة الخدمات المعتمدة | Authoritative service state

| الخدمة               | الحالة                | الدليل التشغيلي الحالي                                                                 |
| -------------------- | --------------------- | -------------------------------------------------------------------------------------- |
| Supabase Preview     | **ACTIVE**            | المصادقة، قاعدة البيانات، Storage الخاص، ودوال Edge مستخدمة في مسارات Preview.         |
| Storage S3           | **ACTIVE**            | التوقيع يتم من الخادم، والعامل لا يحمل مفتاح S3 طويل العمر.                            |
| DigitalOcean Scanner | **ACTIVE**            | العامل outbound-only، ولا توجد منافذ Scanner أو ClamD منشورة للعامة.                   |
| ClamAV               | **ACTIVE**            | التواقيع حديثة؛ الصورة والصوت النظيفان نجحا، وEICAR رُفض.                              |
| OpenAI               | **ACTIVE**            | تشخيص النص والصورة، التفريغ الصوتي، والترجمة نجحت ببيانات اصطناعية في Preview.         |
| Push                 | **PARTIAL**           | إعداد الخادم متقدم، لكن `EXPO_ACCESS_TOKEN` وإثبات الاستلام الموثوق ما زالا مطلوبين.   |
| Maps                 | **EMULATOR VERIFIED** | عرض الخريطة على محاكي Android نجح؛ دقة GPS على جهاز فعلي لم تُختبر.                    |

| Backup               | **RUNBOOK READY**     | مشروع Preview على الخطة المجانية؛ التصدير المقيّد موثق، واختبار الاستعادة الرسمي مؤجل. |

## 2. فحص بداية النافذة التشغيلية | Start-of-window checks

نفّذ الفحوصات التالية من أدوات الإدارة المعتمدة، ولا تنسخ القيم السرية إلى الطرفية أو التذاكر:

1. تأكد أن الهدف هو مشروع Preview وليس Production.
2. سجل SHA المصدر وهوية بناء Android المقصودين في سجل الإصدار.
3. تحقق أن دوال Edge المطلوبة في حالة `ACTIVE` وأن أخطاء المزود تُعرض كفئات منقحة فقط.
4. تحقق أن حاويات العامل وClamD ومحدّث التواقيع تعمل بسياسات إعادة التشغيل المعتمدة.
5. تحقق أن عمر تواقيع ClamAV أقل من 24 ساعة، وأن العامل يواصل polling موقّعًا.
6. تحقق أن لا منفذ Scanner أو ClamD منشور على المضيف أو الإنترنت.
7. راجع مساحة القرص والذاكرة ودوران سجلات Docker، ثم راجع آخر نتيجة cleanup.
8. راجع طابور الإشعارات وdead-letter. لا تفعّل Push كـ `ACTIVE` قبل وجود
   `EXPO_ACCESS_TOKEN` ونجاح إيصال موثوق.
9. تحقق أن إعداد Maps المقيد مرتبط بحزمة Preview وشهادة التوقيع، من دون عرض المفتاح.

## 3. فحص دخاني آمن | Safe smoke procedure

استخدم الحسابات الاصطناعية المعتمدة والبيانات غير الشخصية فقط:

1. سجّل دخول العميل وأنشئ طلب تكييف اصطناعيًا في الرياض عبر الواجهة المعتادة.
2. استخدم تشخيصًا نصيًا اصطناعيًا. لا تُعد fallback نجاحًا لمزود OpenAI.
3. عند الحاجة، استخدم صورة وصوتًا اصطناعيين عبر مسار quarantine → scanner → clean فقط.
4. سجّل دخول مقدم الخدمة، وتحقق من ظهور الطلب والموجز المترجم وإمكانية إنشاء عرض.
5. أكمل الاختيار والمراسلة وحالات المهمة المسموحة والإكمال والتقييم عبر العقود المدعومة.
6. تحقق من رؤية المسؤول للحالة ضمن صلاحياته، ومن ظهور الصحة التشغيلية بلا محتوى خاص.
7. ألغِ أو أكمل بيانات الاختبار وفق سياسة Preview، ثم تحقق من عدم بقاء وسائط أو jobs مؤقتة.

لا تستخدم تحديثات جداول خام لتجاوز التحقق، ولا ترفع وسائط مباشرة إلى المسار النهائي، ولا تمنح
العامل service-role أو قاعدة بيانات أو S3 أو بيانات مستخدم.

## 4. التشغيل اليومي | Daily operations

- **Scanner:** راقب آخر poll، freshness، retry categories، cleanup، مساحة القرص، والذاكرة. أوقف
  claims الجديدة عند stale signatures أو فشل readiness المتكرر؛ لا تروّج quarantine يدويًا.
- **OpenAI:** راقب فئات authentication/quota/model/timeout/rate-limit/5xx فقط. احتفظ بالنص الأصلي
  عند فشل الترجمة، وأظهر عدم توفر المزود بدل نجاح وهمي.
- **Push:** راقب scheduler، retry، dead-letter، وتسجيل/تدوير/إلغاء token. يجب ألا تحتوي payloads
  على نص رسائل أو عناوين دقيقة أو مستندات خاصة.
- **Maps:** راقب أخطاء تقييد الحزمة/التوقيع أو API فقط. التطبيق يستخدم foreground location ولا
  يطلب background location.
- **Supabase:** راقب فئات أخطاء Auth/Edge/Storage المجردة، وحافظ على RLS والتفويض من الخادم.

## 5. النسخ الاحتياطي والاستعادة | Backup and restore readiness

مشروع Preview يعمل على خطة Supabase المجانية. لم تُفعّل خدمة PITR أو استعادة مدفوعة، ولا يجوز
تغيير الخطة ضمن هذا الإصدار.

1. نفّذ تصدير قاعدة بيانات مقيّدًا دوريًا عبر Supabase CLI الرسمي من جهاز إداري موثوق، مع تمرير
   الاتصال من مخزن أسرار وعدم وضعه في الأمر أو السجل.
2. خزّن النسخة مشفرة خارج Git، وسجل وقت UTC وSHA المصدر وهوية migration manifest وسياسة الاحتفاظ.
3. تعامل مع كائنات Storage كنسخة مستقلة؛ نسخ قاعدة البيانات تحفظ metadata ولا تستعيد الكائنات.
4. احتفظ بجرد أسماء الإعدادات والأسرار والمالكين من دون قيمها، وبنسخ إعدادات buckets وEdge وcron.
5. لا تستعد فوق مشروع Preview الوحيد. استخدم هدفًا معزولًا بعد موافقة المالك، ثم اختبر RLS وAuth
   وStorage وEdge ومسارات العميل/مقدم الخدمة قبل أي cutover.

**FORMAL_RESTORE_DRILL_DEFERRED** — اختبار الاستعادة الرسمي، قياس RPO/RTO، والمراجعة المستقلة
مؤجلة إلى تدقيق ما قبل الإطلاق.

راجع أيضًا [Backup and recovery](../operations/BACKUP_AND_RECOVERY.md) وتعليمات Supabase الرسمية
للنسخ الاحتياطي والاستعادة قبل تنفيذ أي أمر قد يغير البيانات.

## 6. الحوادث والتراجع | Incident and rollback

| الحدث                              | الإجراء الآمن                                                                          |
| ---------------------------------- | -------------------------------------------------------------------------------------- |
| Scanner غير جاهز أو التواقيع stale | أوقف claims، أبقِ uploads في quarantine، أصلح readiness، ثم نفّذ canary اصطناعيًا.     |
| اشتباه في سر Scanner               | أوقف العامل، دوّر control وattestation معًا، ارفض العامل/nonce القديم، ثم أعد الاتصال. |
| OpenAI غير متاح                    | أظهر provider unavailable، احتفظ بمدخل المستخدم، ولا تسمِّ fallback نجاحًا مباشرًا.    |
| Push يفشل                          | أبقِ الحدث في retry/dead-letter، ولا ترسل بيانات خاصة في payload أو السجل.             |
| ارتفاع أخطاء Edge                  | أوقف الإجراء المتأثر أو ارجع إلى النسخة المسجلة من الدالة، من دون تغيير Production.    |
| اشتباه تسرب بيانات                 | أوقف المسار، احفظ دليلًا منقحًا، وابدأ خطة الاستجابة للحوادث؛ لا تنسخ المحتوى الخاص.   |

## 7. إنهاء النافذة | End-of-window record

سجل `PASS` أو `FAIL` أو `NOT RUN` لكل مسار، مع SHA ووقت UTC وهوية البيئة فقط. تحقق من cleanup،
عدم وجود بيانات اختبار غير مقصودة، وعدم تنفيذ أي Production أو store action. لا تسجل كلمات مرور أو
JWT أو signed URLs أو مفاتيح أو مسارات وسائط خاصة.

English summary: operate Preview with synthetic data, deny by default, keep the scanner outbound
only, fail closed when Scanner/OpenAI/Push are unavailable, export backups to encrypted storage, and
record evidence without secrets or private content. Production and public-store actions remain out
of scope.
