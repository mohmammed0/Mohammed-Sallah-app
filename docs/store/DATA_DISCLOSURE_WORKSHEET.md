# Production data disclosure worksheet

Engineering inventory, 2026-09-05. This is not a completed Apple privacy label or Play Data Safety form. Map rows to each console's actual categories using the submitted binary, backend flags, processor contracts and SDK behavior. “Collected” and “shared” have platform-specific definitions; a service processor is not automatically the same as a sale or advertising transfer. [Google User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en), [Apple privacy disclosure guidance](https://developer.apple.com/app-store/app-privacy-details/).

For every row record: actual collected fields; optionality and trigger; account linkage; recipients/controller/processor; purpose; hosting/transfers; retention; export/deletion action; consent/withdrawal; and source/build/config evidence. Do not invent durations, legal entity, location or encryption guarantees.

The AI panel withdraws permission for future transfers in the current intake session. It does not retract already transmitted material or promise immediate processor deletion. Account privacy controls start the existing export/deletion workflow. Approved policies must explain the actual request process and lawful retained records. Replacing OpenAI or materially changing transferred content requires updating the disclosure and reviewing consent behavior.

There is no source evidence here to justify claims of end-to-end encryption, zero retention, no collection/sharing, a specific data-residency country, guaranteed deletion deadlines or final “no tracking” answers. Verify runtime services and contracts first. Check the iOS archive's aggregate privacy manifests and required-reason APIs; do not copy arbitrary reason codes simply because an app-level manifest is absent. [Expo privacy manifests](https://docs.expo.dev/guides/apple-privacy/).
