# صَلَح — الدليل العربي

[بوابة اللغات](README.md) · [English](README.en.md)

صَلَح منصة سعودية عربية أولاً لتنسيق الخدمات المحلية بصورة آمنة بين العميل ومقدم الخدمة
الموثق وفرق التشغيل. هذا المستودع متعدد الحزم ويستخدم Supabase بوصفه المصدر المرجعي لقواعد
السوق والتفويض والبيانات، فيما تعتمد تطبيقات الجوال والويب على عقود مشتركة.

## الرؤية

الهدف هو تقليل الغموض في طلب الخدمة ومقارنة العروض وتنفيذ العمل، مع إبقاء القرار البشري
والتفويض من الخادم في المركز. يساعد الذكاء الاصطناعي في تنظيم وصف المشكلة، لكنه لا يوافق على
مقدم خدمة ولا ينشر طلباً ولا ينفذ دفعاً من تلقاء نفسه.

## حالة المستودع

المستودع في مرحلة **الاستعداد لنسخة تجريبية مغلقة** وليس إطلاقاً عاماً أو إنتاجياً:

- سلسلة Draft PRs تحتوي تنفيذ الثقة، فحص الوسائط، الذكاء الاصطناعي، Push/Maps Preview، والرحلات
  الوظيفية للعميل ومقدم الخدمة والإدارة مع واجهة beta مرجعية قابلة للتشغيل.
- Supabase Preview وStorage والماسح الخارجي وOpenAI canaries تعمل وفق أدلة beta الحالية؛ الإنتاج
  لم يُمس.
- يجري الآن توحيد المستودع في فرع تسليم هندسي واحد. الجهاز الفعلي، iOS، Production، القانون،
  النسخ الاحتياطي الرسمي، التنبيهات، والمتاجر تبقى بوابات منفصلة.

التفاصيل والروابط الرسمية في [حالة النسخة التجريبية](docs/status/CLOSED_BETA.md) و
[المتعقب الرئيسي #23](https://github.com/mohmammed0/Mohammed-Sallah-app/issues/23).

## المكونات

| المسار              | الغرض                                                               |
| ------------------- | ------------------------------------------------------------------- |
| `apps/mobile`       | تطبيق Expo Router للعميل ومقدم الخدمة                               |
| `apps/web`          | الموقع العام وصفحات الخصوصية ولوحة التشغيل                          |
| `packages/domain`   | قواعد النطاق وعقود التحقق المشتركة                                  |
| `packages/database` | أنواع قاعدة البيانات المولدة                                        |
| `packages/i18n`     | نصوص العربية والإنجليزية والأردية والهندية                          |
| `supabase`          | migrations وRLS وRPC وStorage وRealtime وEdge Functions والاختبارات |
| `docs`              | الهندسة والأمن والخصوصية والتشغيل والإصدار وأدلة الاستخدام          |

## مبادئ الهندسة والثقة

- تطبيقات العميل تستخدم مفتاح Supabase القابل للنشر فقط؛ مفاتيح الخدمة والخدمات الخارجية
  تبقى في الخادم.
- قواعد السوق موجودة في `packages/domain` أو أوامر قاعدة البيانات الذرية، لا في مكونات العرض.
- المواقع الدقيقة والوسائط المحمية والعروض المختومة لا تُكشف إلا ضمن سياق مصرح به.
- كل تغيير قاعدة بيانات جديد forward-only، وكل سطح مكشوف يبدأ بسياسة RLS تمنع الوصول افتراضياً.
- القيم المالية بوحدات SAR الصغرى الصحيحة، والطوابع الزمنية UTC وتعرض بتوقيت Asia/Riyadh.
- كل نتيجة تحقق تسجل بصدق كـ PASS أو FAIL أو NOT RUN، ولا يحول غياب جهاز أو اعتماد إلى نجاح.

## البدء محلياً

المتطلبات: Node.js 24 LTS وCorepack/pnpm 11.19.0 وDocker Desktop وSupabase CLI 2.114.0.

```bash
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env.local
supabase start
supabase db reset
pnpm dev
```

القيم المحلية تجريبية ومقصودة، ولا يجوز نسخ المفتاح السري المحلي إلى متغيرات
`NEXT_PUBLIC_*` أو `EXPO_PUBLIC_*`. اقرأ [دليل التطوير المحلي](docs/ar/LOCAL_DEVELOPMENT.md).

## التحقق

```bash
pnpm docs:check
pnpm validate
pnpm test:db
pnpm test:e2e:web
```

تتطلب اختبارات قاعدة البيانات Docker. تتطلب اختبارات الجوال الشاملة محاكياً أو جهازاً وتطبيقاً
مثبتاً. راجع [دليل الاختبارات](docs/ar/TESTING.md) لمعنى كل نتيجة.

## الفروع

- `main`: إصدار مستقر أو منشور فقط.
- فرع RC: تكامل مرشح الإصدار الأب.
- فرع beta: تكامل النسخة التجريبية المغلقة.
- فروع milestones: فروع أبناء محدودة تبدأ من رأس beta المعتمد.

لا يدمج هذا التنظيم أي فرع ولا ينشر Production أو متجراً.
